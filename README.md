# VRC Git Sync

VRChatアバター改変用のUnityプロジェクトを、GitHub（private）を通して複数のPC間で同期するエディタ拡張です。
外出先のPCで改変した内容を、メインのPCに「送る」「受け取る」のボタンだけで持っていけます。

## 何が同期されるか

`Assets/` の中は、**自分のフォルダ（例: `Assets/_Mine/`）は中身ごと**、それ以外（配布物）は **`.meta` だけ** を同期します。

| 対象 | 同期 |
|---|---|
| `Assets/<自分のフォルダ>/`（シーン、コピーして改変したマテリアル、アニメーション、テクスチャなど） | する |
| それ以外の `Assets/` の中身（Boothの素体・衣装、zip で配られたテクスチャなど） | しない（各PCでインポートします） |
| それ以外の `Assets/` の `.meta`（ファイルの ID とインポート設定だけ） | する |
| `ProjectSettings/` | する |
| `Packages/` の一覧ファイル（`manifest.json`、`vpm-manifest.json` など） | する |
| `Packages/` の中身（VRChat SDK、lilToon、Modular Avatar など） | しない（各PCで VCC / ALCOM から入れます） |

配布アセットの中身はアップロードしないので、GitHubの容量をほとんど使わず、有料アセットの規約の心配もありません。

Unityは、ファイル同士を GUID（`.meta` に書かれた ID）でつないでいます。`.unitypackage` で入れた配布物は、どのPCでも同じ ID になります。一方、zip で配られた素材をそのまま Assets に置くと、Unity が PC ごとに別々の ID を作ってしまいます。そのため、このツールは配布物の `.meta` だけを同期して、両方のPCの ID をそろえます（下の「zip で配られた素材を使うとき」）。テクスチャの圧縮や最大サイズなどのインポート設定もそろいます。

## 必要なもの

- Unity 2022.3（VRChatが指定するバージョン。同期するPCどうしで同じバージョンにそろえてください）
- git と Git LFS
  - Windows: [Git for Windows](https://git-scm.com/downloads/win)（Git LFS と GitHub へのログイン機能が同梱されています）
  - Mac: 下の「Mac で使う」を見てください
- GitHub のアカウント
- VRChat Avatars SDK（アップロード時の自動記録を使う場合）

### Mac で使う

Windows と同じ `.unitypackage`・同じ GitHub リポジトリで、Windows と Mac の間でも同期できます。Mac では git まわりを Homebrew で入れます。

1. [Homebrew](https://brew.sh/) を入れて、ターミナルで次を実行します。

   ```bash
   brew install git git-lfs
   ```

2. GitHub にログインできるようにします。次のどちらかを使ってください（Mac 標準の設定だけでは、ブラウザでログインできません）。

   ```bash
   brew install --cask git-credential-manager
   ```

   または、GitHub CLI を使う場合:

   ```bash
   brew install gh
   ```

   ```bash
   gh auth login
   ```

   ```bash
   gh auth setup-git
   ```

3. Unity を起動し直してから、初期設定を開きます。初期設定の「git の確認」で、git・Git LFS・ログイン方法が確認できます。

Unity を Finder や Unity Hub から起動すると、Homebrew の場所（`/opt/homebrew/bin`）が PATH に入りません。そのため、このツールは Homebrew の git を直接探し、git を動かすときに Homebrew の場所を PATH に足しています。

VPM パッケージは、Mac では ALCOM などで Windows と同じものを入れてください。Mac から VRChat にアップロードできるかどうかは VRChat SDK 側の対応しだいです。アップロードは Windows で行い、Mac は改変作業に使うのが無難です。

※ Mac での動作は、まだ実機で確認していません。

## インストール

### .unitypackage で入れる（おすすめ）

1. GitHub の Releases から `VrcGitSync-<バージョン>.unitypackage` をダウンロードします。
2. Unity のメニュー **Assets → Import Package → Custom Package...** で選んで、すべてインポートします。
3. `Assets/VrcGitSync/` に入ります。

`Assets/VrcGitSync/` は「自分のフォルダ」の外なので同期されません。**使うPCごとにインポートしてください**（配布アセットと同じ扱いです）。

新しいバージョンに更新するときは、新しい `.unitypackage` を**上書きでインポートするだけ**で大丈夫です。
v0.5.0 以降は、古いバージョンにだけあったファイル（削除・移動したファイル）を、インポートしたときにツールが自動で消します。
そのような更新では、インポートの途中でコンソールに赤いエラーが一瞬出ることがあります。古いファイルを消したあとのコンパイルで自動的に消えるので、そのまま待ってください。
（v0.4.1 以前から v0.5.0 への更新も、消えるファイルがないので上書きだけで大丈夫です）

`.unitypackage` を自分で作る場合は、このリポジトリのルートで次を実行します（Python 3 が必要、Unity は不要）。
`Build~/VrcGitSync-<バージョン>.unitypackage` ができます。

```bash
python Tools~/build-unitypackage.py
```

### Package Manager で入れる

Unity の **Window → Package Manager → ＋ → Add package from git URL...** で、このリポジトリの URL を入力することもできます。
この場合は `Packages/manifest.json`（同期されます）に記録されるので、2台目では自動で入ります。

`.unitypackage` と Package Manager の両方で入れると、同じファイルが2つになってしまうので、どちらか一方にしてください。

## 使い方

### 1台目のPC: 初期設定

1. GitHub で **Private** のリポジトリを作ります。README などは追加せず、空のまま作成してください。
2. Unity のメニュー **Tools → VRC Git Sync → 初期設定** を開きます。
3. 「このPCから始める（1台目）」を選び、次を設定して「初期設定を実行」を押します。
   - **自分のフォルダ**: 同期するフォルダ。シーンや改変したファイルを入れる場所です（新しく作ることもできます）
   - **自分のフォルダに移すシーン**: `Assets` 直下などにあるシーンを、自分のフォルダへ移動します（参照は切れません）
   - **GitHub のリポジトリの URL**: 手順1で作ったリポジトリ
4. 記録されるファイルの一覧（数と合計サイズ）が表示されるので、配布アセットが混ざっていないか確認して「記録する」を押します。
5. 初めて GitHub に送るときは、ログイン用のウィンドウが開きます。ブラウザでサインインしてください。

### 2台目のPC

**すでに同じプロジェクトがある場合（おすすめ）**

1. 配布アセット（Boothの素体・衣装など）と VPM パッケージが、1台目と同じものが入っていることを確認します。
2. このツールの `.unitypackage` をインポートして、**Tools → VRC Git Sync → 初期設定** の「GitHubから取り込む（2台目以降）」に、リポジトリの URL を入れて「取り込む」を押します。
3. 自分のフォルダ・ProjectSettings・パッケージの一覧が GitHub の内容で上書きされます。上書き前の内容は、プロジェクト内の `VrcGitSyncBackup/` にバックアップされます。
4. 取り込み後は、Unity を一度再起動しておくと確実です。

**新しく用意する場合**

1. ターミナルで clone します。

   ```bash
   git clone https://github.com/<ユーザー名>/<リポジトリ名>.git
   ```

2. VCC / ALCOM で、clone したフォルダを既存のプロジェクトとして追加して開きます（VPM パッケージはここで入ります）。
3. 1台目と同じ配布アセットと、このツールの `.unitypackage` をインポートしてから、自分のフォルダのシーンを開きます。

### ふだんの使い方

- **Unity を開いたとき**: もう一方のPCで送った変更があれば「受け取りますか？」と聞かれます。作業を始める前に受け取ってください。
- **作業が終わったら**: **Tools → VRC Git Sync → 同期ウィンドウ** の「送る」を押します。Unity を閉じるときにも、送っていない変更があれば聞かれます。
- **もう一方のPCで**: 「受け取る」を押すか、Unity を開いたときの確認で受け取ります。

両方のPCで同じファイルを変更していた場合は、「このPCの内容を使う」「もう一方のPCの内容を使う」のどちらかを選びます。
（中身を混ぜることはしません。選ばなかった方の内容も履歴には残ります）

### VRChat へのアップロード

アップロードが成功すると、その時点の状態が自動で記録され、`upload/アバター名/日時` という印（タグ）が付きます。
GitHub へは次に「送る」を押したときにまとめて送られます。同期ウィンドウの「最近のアップロード」に一覧が出ます。

### 自分のフォルダの外に保存したとき

自分のフォルダの外にあるファイルは同期されないので、保存した瞬間にウィンドウで知らせます。

- **配布物のマテリアルなどを変更した**: 「自分のフォルダにコピーして差し替える」を押すと、自分のフォルダにコピーを作って参照をコピーに切り替え（下の「自分のフォルダにコピーして使う」と同じ）、配布物のファイルは変更前の内容に戻します。
  （シーンのインスペクターでマテリアルの色などを変えた場合も、実際にはマテリアルのファイルが書き換わっています）
- **フォルダの外に新しいファイルを作った／フォルダの外のシーンを保存した**: 「自分のフォルダに移動する」で移動できます。
- **ツールが勝手に書き込むフォルダなど**: 「このフォルダは今後警告しない」を押すと、以後は知らせません。

プレイモード中、VRChat SDK のビルド・アップロード中、`.unitypackage` のインポート中は知らせません。

保存（Ctrl+S）せずに「送る」「受け取る」を押した場合や、Unity を閉じるときに送る場合も、送る前の保存で配布物の変更が見つかれば確認が出ます。「自分のフォルダに入れてから続ける」を選ぶと、コピーと差し替えをしてから送ります。VRChat へのアップロード時の記録で見つかった場合は、記録のあとで警告のウィンドウが出ます。

### 自分のフォルダにコピーして使う（右クリックメニュー）

Project ウィンドウでファイルやフォルダを選んで、右クリック → **VRC Git Sync → 自分のフォルダにコピーして使う** を選ぶと、次のことをまとめて行います。

1. 自分のフォルダの中に、元と同じ並びでコピーします（例: `Assets/ShopName/AvatarName/Face.mat` → `Assets/_Mine/ShopName/AvatarName/Face.mat`）
2. 自分のフォルダ内のシーン・アニメーション・コントローラーなどにある参照を、コピーに切り替えます（フォルダをコピーした場合、コピーどうしの参照もつながります）
3. 開いているシーンでは、配布物のプレハブから引き継いでいる参照（アバターの体のマテリアルなど）も、シーン側の上書きとしてコピーに切り替えます

元のファイルはそのまま残ります。コピーは新しい GUID になるので、もう一方のPCの配布物とぶつかることはありません。

### zip で配られた素材を使うとき

`.unitypackage` ではなく zip で配られた素材（テクスチャセットなど）は、Assets に置くと Unity が PC ごとに別々の ID を作ります。そのままだと、もう一方のPCで lilToon のサブカラーなどに設定したテクスチャが見つかりません。このツールは、次のようにして ID をそろえます。

- **配布物の `.meta` を同期する**: 「送る」と、配布物の `.meta`（ID とインポート設定。画像などの中身は入っていません）も GitHub に記録します。先に記録した PC の ID が「正しい ID」になります
- **置いた瞬間にそろえる**: もう一方のPCに同じ素材を置くと、Unity が作った新しい ID を、すぐに GitHub に記録されている ID に置き換えます
- **受け取ったときにそろえる**: 両方のPCで別々に素材を入れていた場合は、「受け取る」で、このPCの ID がもう一方のPCの ID に置き換わります
- **それでもずれているとき**: 同期ウィンドウに「ID が GitHub と違う配布物」が出たら、「GitHub に合わせる」を押してください

配布物がまだ入っていないPCでは、Unity がその配布物の `.meta` を消しますが、その削除は GitHub に送りません（もう一方のPCの ID は消えません）。

#### v0.3 以前から使っている場合

v0.3 以前は配布物の `.meta` を同期していなかったので、zip の素材の ID が PC ごとにずれていることがあります。どちらの PC の ID に合わせるかは、**先に「送る」をした PC** で決まります。

1. 両方の PC で、このツールを v0.4 以降に更新します
2. ずれている素材を使って設定したほうの PC で、先に「送る」を押します（もう一方の PC では、まだ送らないでください）
3. もう一方の PC で「受け取る」を押します

自分のフォルダに「この PC では見つからない参照」がある状態で、配布物の ID を初めて記録しようとすると、確認が出ます。その参照を作ったのがもう一方の PC なら、「あとで」を選んで、もう一方の PC で先に送ってください。

### 自分のフォルダ以外に同期するフォルダ

ツールの中には、作ったファイルを決まった場所に書き出すものがあります（例: FaceEmo の `Assets/Suzuryg/FaceEmo/Generated`）。
そのフォルダを追加しておくと、自分のフォルダと同じように中身ごと同期されます。

- **追加のしかた**: Project ウィンドウでフォルダを右クリック → **VRC Git Sync → このフォルダも同期する**。または、同期ウィンドウの「設定」→「フォルダを追加…」
- 追加した設定はもう一方のPCにも届くので、追加するのは片方のPCだけで大丈夫です
- Booth の素体や衣装などの配布物のフォルダは追加しないでください（有料アセットが GitHub に上がってしまいます）
- **外すとき**: 同期ウィンドウの「設定」で「外す」を押します。GitHub からそのフォルダのファイルが外れるので、もう一方のPCでは、次に「受け取る」とそのフォルダのファイルが消えます（外したPCのファイルは残ります）

#### FaceEmo を使うとき

FaceEmo の表情メニューのデータはシーンに保存されるので、シーンと一緒に同期されます。あとは次の2つをしておくと、もう一方のPCでもそのまま動きます。

1. 表情のアニメーションを保存するとき、最初の1回は自分のフォルダの中（例: `Assets/_Mine/FaceEmo/`）を選ぶ（2回目からは同じ場所が選ばれます）
2. 一度「アバターに適用」したあとで、`Assets/Suzuryg/FaceEmo/Generated` を同期するフォルダに追加する

### すでに改変しているプロジェクトに入れるとき

保存したときの警告は、ツールを入れたあとの保存にしか出ません。それより前に配布物を直接変えていた場合や、ツールが配布物のフォルダの中にファイルを作っていた場合は、そのままでは同期されません。初期設定のあとで、次のようなものを右クリック → **自分のフォルダにコピーして使う** で移してください。

- 直接色などを変えた配布物のマテリアル
- インポート設定（圧縮・最大サイズなど）を変えた配布物のテクスチャ（そのテクスチャを使うマテリアルも、一緒にコピーしてください）
- 配布物のフォルダの中に生成されたファイル（例: Supine の `Generated` フォルダ）

アバターのシーンを開いた状態で実行すると、シーン内の参照もまとめて切り替わります。

## 困ったとき

| 症状 | 対処 |
|---|---|
| GitHub に送れない（認証エラー） | Windows: 初回はログイン用のウィンドウが開きます。開かない場合は、ターミナルでプロジェクトのフォルダに移動して `git push` を一度実行し、ログインしてください。Mac: 「Mac で使う」の手順2（Git Credential Manager か GitHub CLI）を済ませてください |
| 「すでにデータがあります」と出る | 1台目の初期設定では、空のリポジトリを使ってください。2台目なら「GitHubから取り込む」を使います |
| 大きいファイルを LFS に移したと出る | 50MB を超えるファイルは自動で Git LFS の対象になります（GitHub は 100MB を超えるファイルを受け付けないため） |
| Unity のバージョンが違うと出る | 2台の Unity のバージョンをそろえてください |
| 受け取ったのに表示がおかしい | 配布アセットや VPM パッケージのバージョンが2台で同じか確認してください |

GitHub の Git LFS は、無料で保存容量 10GiB・転送量 月10GiB まで使えます（2026年11月時点）。
配布アセットは送らないので、ふつうはこの範囲に収まります。

## 今はできないこと（v0.6）

- 衝突したファイルを1つずつ選ぶ（今は衝突したファイルをまとめてどちらかにそろえます）
- 履歴の一覧や、過去のバージョンに戻す画面
- 必要な配布アセットの一覧と、足りないものの表示
- 自分のフォルダの変更（初期設定のあとで変える場合は、`.gitignore` と `ProjectSettings/VrcGitSync.json` を手で直す必要があります）
- 「コピーして使う」は、開いていないシーンで配布物のプレハブから引き継いでいる参照と、配布物のフォルダ内のファイル（配布物のプレハブなど）の中の参照は切り替えません

設計の考え方は [Documentation~/design.md](Documentation~/design.md) にまとめています。
