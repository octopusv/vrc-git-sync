# VRC Git Sync 設計メモ

## 目的

VRChatアバター改変用のUnityプロジェクトを、外出先のPCと自宅のメインPCの間で楽に同期すること。
履歴を残したり過去に戻したりするのは二の次。

## 前提

- 形: Unityエディタ拡張。パッケージ名は `io.github.octopusv.vrc-git-sync`
  - VCC / ALCOM（VPM）で `Packages/io.github.octopusv.vrc-git-sync/` に入れる（v0.7.0〜）。入れたことは `Packages/vpm-manifest.json` に記録され、同期される
  - `.unitypackage` で `Assets/VrcGitSync/` に入れることもできる。自分のフォルダの外なので同期されない。使うPCごとにインポートする
  - Package Manager の git URL でも入れられる
- 使う人: まず自分。gitに詳しくないVRChatユーザーにも配れる形にする
- リモート: privateのGitHubリポジトリ（Git LFSを使用）
- 1つのUnityプロジェクトに複数のアバターが入っている
- 配布アセット（Boothの素体・衣装など）は、改変するときにコピーしてから使う

## 何を同期するか

`Assets/` の中は **自分のフォルダ（例: `Assets/_Mine/`）だけ** を同期する。それ以外の `Assets/` はすべて同期しない。

| 対象 | 同期 |
|---|---|
| `Assets/<自分のフォルダ>/`（シーン、コピーして改変したマテリアル、アニメーション、テクスチャなど） | する |
| `Assets/` のそれ以外の中身（Boothの素体・衣装、ツールのサンプルなど） | しない（各PCでインポートする） |
| `Assets/` のそれ以外の `.meta`（GUID とインポート設定）（v0.4〜） | する |
| `ProjectSettings/` | する |
| `Packages/manifest.json`、`packages-lock.json`、`vpm-manifest.json` | する |
| `Packages/` のそれ以外（VPMパッケージの中身） | しない（VCC/ALCOMで入れる） |
| `Library/`、`Temp/`、`Logs/`、`UserSettings/` など | しない |

これで動く理由: Unityはファイル同士をGUID（`.meta`）で参照している。`.unitypackage` はインポートしてもGUIDが変わらないので、
もう一方のPCで同じパッケージを入れれば、シーンや改変ファイルからの参照がそのままつながる。

このルールにした理由:
- 配布アセットを送らないので、GitHubのLFS容量をほとんど使わない
- 有料アセットをアップロードしないので、規約の心配がない
- 他の人に配っても「アセットは各自で用意する」で済む

## 注意点と対策

| 注意点 | 対策 |
|---|---|
| シーンをAssets直下などに置いていると同期されない | 初期設定でフォルダの外のシーンを見つけて、まとめて自分のフォルダに移動する（GUIDは変わらない） |
| 配布物のマテリアルを直接いじると、その変更は同期されない（シーンのインスペクターで変えても `.mat` が書き換わる） | 保存した瞬間に警告し、ワンクリックで「自分のフォルダにコピー → 開いているシーンの割り当てを差し替え → 配布物は保存前の状態に戻す」 |
| 自分のファイルをうっかりフォルダの外に作ってしまう | 保存・作成した瞬間に警告し、ワンクリックで自分のフォルダに移動 |
| ツールが勝手にフォルダの外に書き込む | 「このフォルダは今後警告しない」。NDMFの一時フォルダ、プレイモード中、SDKのビルド中、パッケージのインポート中は最初から警告しない |
| 2台のPCで同じファイルを変更して衝突する | 起動時に新着を確認して受け取りを促す。終了時に送っていない変更があれば送信を促す。それでも衝突したら「このPCの内容／もう一方の内容」を選ぶだけにする（中身は混ぜない。選ばなかった方も履歴には残る） |
| 100MBを超えるファイルはGitHubに送れない | コミット前に大きいファイルを見つけたら、自動でLFSの対象に追加する |
| 2台のPCでUnityのバージョンが違う | 受け取ったときに `ProjectVersion.txt` を比べて警告する |
| パッケージのバージョンが2台で違う | 今は各自でそろえる（必要アセット一覧は後で） |

## 機能（v0.1）

1. 初期設定ウィザード
   - git・Git LFSの確認、gitのユーザー名・メールの設定
   - 1台目: 自分のフォルダの選択、外にあるシーンの移動、`.gitignore`/`.gitattributes` の生成、`git init`、最初のコミット、GitHubへの送信
   - 2台目以降: GitHubから取り込む（既存のプロジェクトに、自分のフォルダと設定を上書きで取り込む。上書き前にバックアップ）
2. 同期ウィンドウ: 送る／受け取る、状態表示（送っていない変更・新着）、最近のアップロード、設定
3. 起動時チェック（新着があれば受け取りを促す）・終了時チェック（送っていない変更があれば送信を促す）
4. アバターのアップロード成功時に自動でコミットし、`upload/<アバター名>/<日時>` のタグを付ける（pushは次の「送る」でまとめて）
5. 自分のフォルダの外での保存・作成の警告（配布物はコピーして差し替え・元に戻す、新しいファイル・シーンは移動）
6. 右クリックメニュー「自分のフォルダにコピーして使う」（v0.2）: すでに直接改変してしまった配布物や、配布物のフォルダに生成されたファイルを移すため
   - コピー先は `<自分のフォルダ>/<元のパス>`。コピーは新しい GUID になるので、もう一方のPCの配布物と GUID が重複しない（移動だと重複する）
   - 参照の切り替えは2段階: 自分のフォルダ内のテキスト形式のアセットの `guid:` を書き換え、開いているシーンでは SerializedObject で配布物のプレハブから引き継いだ参照も上書きする

7. 配布物の `.meta` の同期（v0.4）: zip で配られた素材は PC ごとに GUID が変わり、もう一方のPCで設定した参照が切れるため
   - 中身は同期せず `.meta`（GUID とインポート設定）だけを同期する。.gitignore は `/Assets/**` → `!/Assets/**/` → `!/Assets/**/*.meta` → `!/Assets/<自分のフォルダ>/**` の順
   - GitHub（HEAD）にある GUID を正とする
     - 記録するとき: 配布物の `.meta` の削除は記録しない（配布物がないPCで Unity が消すため）。HEAD と GUID が違う `.meta` も記録しない
     - 配布物の `.meta` は、GitHub の変更を取り込んだあとで記録する（先に記録すると、もう一方のPCが同じ場所に記録したものとぶつかるため）。「受け取る」とアップロード時の記録には含めない
     - 取り込むとき: もう一方のPCが追加した `.meta` と同じ場所にある、このPCの未記録の `.meta` を消してから merge する（GitHub の GUID で置き換わる）
     - 置いた瞬間: AssetPostprocessor で `importSettingsMissing`（Unity がその場で `.meta` を作った）を検出し、HEAD に同じパスの `.meta` があれば HEAD の内容に戻す
     - それでもずれたもの（並列インポートで検出できなかった場合など）は、同期ウィンドウの「GitHub に合わせる」で HEAD に戻す
   - 初めて配布物の `.meta` を記録するとき、自分のフォルダにこのPCで解決できない GUID があれば確認する（その参照を作ったPCで先に記録したほうがよいため）

8. 同期の前の保存でも、自分のフォルダの外への保存を検出する（v0.4.1）
   - 以前は同期の処理中（Busy）は警告を止めていたため、保存せずに「送る」と、配布物の変更が黙って同期されなかった
   - 「送る」「受け取る」「終了時の送信」の前の保存を SaveWatcher.Capture で集め、中身が変わったものがあれば「自分のフォルダに入れてから続ける／やめる／このまま続ける」を聞く
   - アップロード時の記録で見つかったものは、記録のあとで警告のウィンドウに出す
   - 終了時のチェックで、シーンだけでなく保存していないアセット（マテリアルなど）も「送っていない変更」として扱う

9. 上書きインポートでの更新（v0.5.0）
   - `.unitypackage` はファイルを追加・上書きするだけで消せないので、ビルド時に git の履歴から「前のバージョンにあって今はないファイル」の GUID を集めて `UpdateInfo.txt`（GUID 固定）に書く
   - Unity はどこかにコンパイルエラーがあると新しいコードを読み込まないので、消す処理は「インポート中にまだ動いている古いバージョンの PackageUpdater」が、コンパイルの前に行う（スクリプトの読み込み直後にも念のため確認する）
   - 消すのは UpdateInfo.txt があるフォルダ（ツールのフォルダ）の中のものだけ

10. 自分のフォルダ以外に同期するフォルダ（v0.6.0）
    - ツールが決まった場所に書き出すもの（FaceEmo の `Assets/Suzuryg/FaceEmo/Generated` など）を中身ごと同期するため。設定の `extraFolders`
    - .gitignore では自分のフォルダと同じように `!/<フォルダ>/**` を足す。記録・状態表示・保存時の警告・ID の扱いでも、自分のフォルダと同じに扱う（SyncSettings.SyncedFolders / IsSynced）
    - 外すときは `git rm -r --cached` で記録から外す（このPCのファイルは残る。もう一方のPCでは受け取ると消える）。.meta は配布物と同じように同期し続ける
    - Assets 自体や、自分のフォルダを含むフォルダ、自分のフォルダの中のフォルダは追加できない

11. VPM での配布（v0.7.0）
    - パッケージ名を仮の `com.vrcgit.sync` から `io.github.octopusv.vrc-git-sync` に変えた（VPM の一覧を置く GitHub Pages のドメインに合わせた）
    - `Tools~/build.py` が、`.unitypackage` に加えて、VPM 用の zip（package.json がルート）と一覧の `index.json` を作る。zip は Release に添付し、一覧は gh-pages ブランチ（GitHub Pages）に置く
    - `.unitypackage` 版と VPM 版の両方が入ると、同じ名前のアセンブリが2つになり、どちらもコンパイルできなくなる（どちらのコードも動かないので、ツールの中では直せない）。そのため、二重になる前に片方を消す
      - VCC / ALCOM で直接入れたとき: package.json の `legacyFolders` に `Assets/VrcGitSync` の GUID を書いておき、VCC / ALCOM に消してもらう
      - もう一方のPCが切り替えた内容を受け取ったとき: `.unitypackage` 版（v0.7.0〜）が、`vpm-manifest.json` / `manifest.json` にこのツールが書かれたことに気づいて、自分のフォルダを消すか聞く（LegacyInstallCheck）。VPM の Resolve で実際に入るのは、その後に VCC / ALCOM からプロジェクトを開いたとき

12. 外から入れたファイルの扱い（v0.7.1）
    - 以前は、自分のフォルダの外に新しいファイルができると、Unity の中で作ったものも外から入れたもの（zip の素材など）も同じに扱い、1ファイルずつ「自分のフォルダに移動」を勧めていた。外から入れた配布物を移すと、中身が GitHub に上がり、もう一方のPCの同じ素材と ID がぶつかる
    - 見分け方: Unity の中で作ったファイル（CreateAsset、シーンの別名保存、CopyAsset）は、OnWillCreateAsset がまだファイルのない状態でファイル自体のパスで呼ばれ、そのあと .meta のパスで呼ばれる。外から入れたファイルは、ファイルがある状態で .meta のパスでだけ呼ばれる（Unity 2022.3 で確認）
    - 外から入れたファイルは、いっしょに新しくできたフォルダのいちばん上（既存のフォルダに入れたならそのフォルダ）ごとにまとめて、「配布物として扱う」「このフォルダも中身ごと同期する」を聞く。配布物にしたフォルダは設定の `vendorFolders` に残し（2台で共有）、以後は聞かない
    - Unity の中で作ったファイルも、同じフォルダのものはまとめて出す。まとめて移動するときは、フォルダの中の並びを保つ
    - ツールが File.WriteAllBytes などで書き出して読み込ませたファイルは、外から入れたものと区別できない

## 実装メモ

- gitは自前で持たず、Git for Windowsの `git` を呼び出す（LFSとGit Credential Managerが同梱されているため）
- git操作はバックグラウンドスレッドで実行し、Unity APIの呼び出し（保存・Refresh・ダイアログ）はメインスレッドで行う
- 設定はプロジェクトごとに `ProjectSettings/VrcGitSync.json` に保存する（2台で共有される）
- `.gitignore` と `.gitattributes` は、ツールが管理する区間だけを書き換える（手で書いた部分は残す）
- VRChat SDKとの連携は別のアセンブリに分け、`com.vrchat.avatars` が入っているときだけコンパイルする

## リリースの手順

1. `package.json` の `version` を上げてコミットし、push する。タグ `v<version>` を付けて push する
2. `git fetch origin gh-pages` のあとで `python Tools~/build.py` を実行する（gh-pages にある一覧に、今のバージョンが足される）
3. GitHub に Release `v<version>` を作り、`Build~/` の `.unitypackage` と zip を添付する
4. `Build~/pages/` の中身（`index.json`、`index.html`、`.nojekyll`）を gh-pages ブランチに置いて push する（Release の zip を添付してから。一覧の URL が zip を指すため）
